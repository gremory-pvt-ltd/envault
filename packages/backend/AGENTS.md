# backend (`packages/backend`) — agent rules

Express 4 + TypeScript (ESM) + Prisma 7 + better-auth on SQLite.

## Package manager

- Part of the root pnpm workspace. Install from the repo root only.
- Scripts: `pnpm --filter ev-backend dev|build|test|db:migrate|db:generate`.

## Data layer

- Prisma 7 uses the `prisma-client` generator into `src/generated/prisma/`
  (gitignored, regenerated by `prisma generate`) and the
  `@prisma/adapter-better-sqlite3` driver adapter at runtime.
- `prisma.config.ts` holds the schema path and `DATABASE_URL`; `prisma/schema.prisma`
  has the datasource provider only.
- Schema changes: edit the schema, then `pnpm db:migrate -- --name <change>`.
  Commit `prisma/migrations/`. In production run `prisma migrate deploy` before
  reloading PM2; never use `db push` in production.
- Runtime Pragmas (`WAL`, `busy_timeout`, `foreign_keys`) are set in
  `src/db.ts` via `configureSqlite()`.
- SQLite is single-writer: run **one** API process. Do not enable PM2 cluster
  mode or multiple instances.

### Plaintext values — read this

Secret values are stored plaintext **by explicit product decision**. The DB file
and every backup are secret material. Therefore:

- Never enable Prisma query logging in production (`log: ["error"]` only).
- Never log bodies, values, raw request payloads or full error objects that may
  contain values.
- Never put a value in audit metadata, URLs, filenames or error messages.
- Error responses are generic; details only for Zod field errors.
- Keep the DB outside the repo; permissions/backup rules live in
  `docs/security.md`.

## Auth and permissions

- better-auth: email/password, `disableSignUp: true`, `admin` plugin
  (`admin`/`member` roles), `twoFactor` TOTP plugin.
- `requireAuth` (`src/auth.ts`) attaches `req.user` / `req.session`.
- `requireAdmin` (`src/middleware.ts`) gates project/environment writes and
  member management.
- All authenticated members may reveal, create, edit, delete, import and export
  secrets in every environment. Admin-only: project CRUD/archive, environment
  CRUD, member creation/roles/blocking/password resets.
- User passwords are hashed with `hashPassword` from `better-auth/crypto`
  (`scripts/create-admin.ts`, `routes/members.ts`); credential accounts use
  `providerId: "credential"` and `accountId: user.id`.
- Blocking a member sets `banned` and deletes their sessions.
- The SPA and API are different origins. CORS allows exactly `FRONTEND_URL` with
  credentials; better-auth `trustedOrigins` must match. `requireTrustedOrigin`
  additionally checks `Origin` on non-GET requests.
- The better-auth handler must be mounted **before** `express.json()`.

## Audit

Every meaningful action writes `auditEvent` via `src/lib/audit.ts`:

- `secret.created|updated|deleted|revealed|restored`
- `secrets.imported`, `environment.exported`
- `project.created|updated|archived`
- `environment.created|updated|deleted`
- `member.created|updated|password_reset`

Audit rows are append-only, store an actor email snapshot, and contain key names
(never values). Keep the `metadata` payload small and value-free.

## API conventions

- Routes mount under `/api` in `src/index.ts`; everything except `/health` and
  `/api/auth/*` requires auth.
- Validate every body/query with Zod (`parseBody`/`parseQuery`).
- Success: `{ "data": … }`; error: `{ "error": { code, message, details? } }`.
- Wrap async handlers in `asyncHandler` (Express 4 does not catch rejections).
- 401/403/404/409 use `HttpError`/`notFound`; the global handler hides internals.
- Reveal/export responses set `Cache-Control: no-store`; export also sets a
  filename. CORS exposes `Content-Disposition`.
- Rate limits: sign-in 20/15 min/IP; do not remove.

## Tests

- `pnpm --filter ev-backend test` runs node:test through `tsx`.
- Add tests for pure logic (dotenv parsing/serialization, permissions, audit
  metadata). Never write tests that assert secret values into logs or fixtures.
- Prefer `supertest` for route tests; set an `Origin: <FRONTEND_URL>` header on
  non-GET requests, or the trusted-origin guard returns 403.
