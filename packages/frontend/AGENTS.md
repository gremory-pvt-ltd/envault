# frontend (`packages/frontend`) — agent rules

Vite + React 19 + TypeScript + Tailwind 4 + TanStack Router/Query + shadcn
(base-ui flavor, `style: base-luma`, `baseColor: mauve`).

## Package manager

- Part of the root pnpm workspace. Install from the repo root (`pnpm install`).
- Use `pnpm` only; never `npm`/`yarn`.
- Run scripts with `pnpm --filter ev-frontend <script>`.

## UI: shadcn only — skills + MCP first

We do not hand-roll UI primitives. The registry is the source of truth.

1. **Load the shadcn skill** (`.agents/skills/shadcn/SKILL.md`) before any
   component work.
2. **Search the shadcn MCP** (`search_items_in_registries`,
   `view_items_in_registries`, `get_item_examples_from_registries`) and the CLI:
   - `pnpm dlx shadcn@latest search -c packages/frontend`
   - `pnpm dlx shadcn@latest view <item> -c packages/frontend`
   - `pnpm dlx shadcn@latest docs <item> -c packages/frontend`
3. **Add it from the registry**:
   - `pnpm dlx shadcn@latest add <component> -c packages/frontend`
   - Add several at once: `… add button card dialog table -c packages/frontend`
4. **Only if no registry item fits**, write a custom component under
   `src/components/` (never under `ui/`). Prefer composing a registry component.
5. `src/components/ui/**` is managed by shadcn. Do **not** create, edit or delete
   files there without explicit user confirmation. Add/update via the CLI.
6. `src/index.css` is shadcn-managed — do not edit it. App-specific CSS goes in
   `src/theme.css`, imported after `index.css` in `main.tsx`.
7. Icons come from `lucide-react`. Toasts use `sonner` via
   `src/components/app-toaster.tsx`.
8. This project uses **base-ui** (`@base-ui/react`), not Radix. Never paste
   Radix-based shadcn snippets. Base UI buttons that render an anchor need
   `nativeButton={false}`, or just style a `Link` with `buttonVariants`.

Installed components live in `src/components/ui/` and their dependencies are
already in `package.json`. Keep `components.json` in sync with the repo style
(`base-luma`, `baseColor: mauve`, aliases `@/components`, `@/lib/utils`).

## Routing — TanStack Router, file-based

- Routes are files in `src/routes/`; `__root.tsx` renders the root `<Outlet />`.
- Pathless layout: `_app.tsx` (auth guard + shell). Pages: `_app.index.tsx`,
  `_app.audit.tsx`, `_app.team.tsx`, `_app.settings.tsx`,
  `_app.projects.$projectId.tsx` (layout + environment tabs),
  `_app.projects.$projectId.env.$envId.tsx` (secrets),
  `_app.projects.$projectId.settings.tsx`.
- Never hand-roll routing with state or `window.location`. Use `Link`,
  `useNavigate`, `Navigate`, `createFileRoute`.
- `src/routeTree.gen.ts` is generated by `@tanstack/router-plugin`; commit it,
  never edit it. Running Vite regenerates it.
- Auth guard lives in `_app.tsx` `beforeLoad`; it uses the shared session query.
  Login clears the cached session miss before navigating.

## Data — TanStack Query only

- All server state uses `useQuery`/`useMutation` through `src/lib/api.ts`.
- Query options factories live in `src/lib/queries.ts`. Reuse them; do not create
  parallel keys.
- No bare `fetch` in components. Mutations invalidate the relevant keys
  (`secrets`, `projects`, `project`, `audit`, `members`).
- The API helper always sends `credentials: "include"` (cross-origin cookies).
  Never cache secret values in `localStorage`/`sessionStorage`.
- Server errors are `ApiError`; surface `error.message` with a `sonner` toast.

## LAN development

- `vite.config.ts` binds `host: "0.0.0.0"`, port 5173 (falls forward if busy).
- `VITE_API_URL` must be `http://<LAN_IP>:5000`, never `localhost`.
- Test from another LAN device; cookies/`trustedOrigins` are origin-exact.
- Plain HTTP LAN has no async clipboard; `src/lib/clipboard.ts` keeps the
  `execCommand` fallback.

## Quality bar

- `pnpm --filter ev-frontend build` (tsc + vite) must pass.
- No unused locals/params; TypeScript is strict.
- Keep the dark-only look: `html.dark`, Geist, violet accents, rounded cards.
- Check empty, loading, error and mobile states for every new screen.
